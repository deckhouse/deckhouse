---
title: Сервис-меш
description: Инфраструктурный слой, который управляет сетевым взаимодействием между сервисами приложения. Шифрование, контроль доступа, маршрутизация, повторы запросов и сбор метрик настраиваются централизованно, без изменения кода сервисов.
lang: ru
---

Сервисы приложения обмениваются запросами по сети, и без сервис-меша каждый из них должен сам реализовывать шифрование, проверку прав, повторы и тайм-ауты. Сервис-меш берёт эти задачи на себя: трафик между сервисами проходит через прокси, которые настраиваются из одной точки. Обычно прокси добавляется в под приложения как сайдкар-контейнер. В экспериментальном режиме ambient прокси работает на уровне узла, и сайдкары в подах не нужны.

В Deckhouse Platform сервис-меш предоставляет модуль [`istio`](/modules/istio/). Внутри одного кластера он используется, например, для [Canary-развёртывания](glossary.html#canary-deployment) и автоматического отключения сбойного сервиса (Circuit Breaker). На его основе строятся [федерация](glossary.html#federation) и [мультикластер](glossary.html#multicluster).

Подробнее в разделе [«Межкластерное взаимодействие»](admin/configuration/network/alliance/).
