В Deckhouse Platform кворум важен прежде всего для etcd — хранилища [control plane](glossary.html#control-plane). Кластер etcd принимает изменения, только пока доступно большинство его участников (N/2 + 1): кластер из трёх участников выдерживает отказ одного участника, кластер из пяти — отказ двух. Чётное число участников не повышает отказоустойчивость: при двух участниках отказ любого из них приводит к потере кворума. Поэтому используйте нечётное число [master-узлов](glossary.html#master-node), как правило три. В конфигурации с двумя master-узлами третий экземпляр etcd может работать на [arbiter-узле](glossary.html#arbiter-node), который обеспечивает кворум.

Подробнее в разделе [«Отказоустойчивость»](admin/configuration/platform-scaling/control-plane/control-plane-recovery-and-debugging.html#отказоустойчивость) руководства по восстановлению control plane.
