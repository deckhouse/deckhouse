В Deckhouse Platform доступны три механизма: [проверка подписи образов](glossary.html#image-signature-verification) пользовательской нагрузки на этапе валидации запросов к API Kubernetes, [рантайм-аудит](glossary.html#runtime-audit) работающих контейнеров и защита целостности модулей Deckhouse Platform. Криптографическая проверка подписи образов на уровне контейнерного рантайма (CRI) с защитой распакованных слоёв через DM-Verity доступна только в сертифицированных [редакциях](glossary.html#edition).

Начиная с версии 1.74 модули устанавливаются как образы EROFS, смонтированные только для чтения через DM-Verity, что защищает установленный модуль от подмены и изменения на узле. Механизм включается автоматически, если ОС узла поддерживает модуль ядра `erofs`. Без него Deckhouse Platform продолжает работу и выводит алерт.

Подробнее в разделе [«Контроль целостности»](architecture/security/integrity-control.html).
