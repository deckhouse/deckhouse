Для георезервирования в каждом регионе разворачивают по одному кластеру Deckhouse Platform и объединяют их декларативным API в [мультикластер](glossary.html#multicluster): с помощью встроенного [сервис-меша](glossary.html#service-mesh) на основе Istio или сетевого функционала платформы на базе Cilium. Приложение должно уметь работать параллельно в разных регионах, а между регионами должен существовать стабильный сетевой канал. Правильно настроенная система сохраняет работу приложения даже при выходе из строя целого [региона](glossary.html#region) или облака.

Входящий трафик в мультикластере балансирует внешний балансировщик по одной из двух схем: [active-active](glossary.html#active-active) или [active-standby](glossary.html#active-standby). Балансировку и организацию хранилищ настраивает администратор кластера. Георезервирование — один из двух подходов к [катастрофоустойчивости](glossary.html#disaster-resilience). Второй — [геораспределённость](glossary.html#geo-distribution).

Подробнее в разделе [«Георезервирование»](architecture/disaster-resilience/geo-reserving.html).
