Модуль [`adaptive-resource-management`](/modules/adaptive-resource-management/) позволяет автоматизировать подбор resource requests и limits для рабочих нагрузок на основе рекомендаций Vertical Pod Autoscaler (VPA).

Модуль разворачивает контроллер **AutoVPA**, основанный на [Goldilocks](https://github.com/FairwindsOps/goldilocks), но с дополнительными доработками Deckhouse, который автоматически создает и поддерживает объекты VPA для рабочих нагрузок в выбранных пространствах имен и предоставляет рекомендации по ресурсам. AutoVPA заменяет ручной подбор параметров «на глаз» для каждого приложения объективными, основанными на реальном потреблении рекомендациями сразу для всего парка workload'ов: это предотвращает избыточное резервирование ресурсов, которое увеличивает расходы на инфраструктуру, обеспечивает предсказуемую производительность приложений за счёт requests и limits, основанных на фактическом потреблении, а не на оценках, и масштабирует один и тот же процесс подбора ресурсов на любое количество workload'ов и namespace'ов — без изменения манифестов.

Основные возможности:

* Автоматическое создание объектов VPA для Deployments, StatefulSets, DaemonSets и Jobs в управляемых пространствах имен.
* Гибкий выбор пространств имен: управление всеми пространствами имен, только пространствами имен с определенным лейблом или пространствами имен, соответствующими label selector.
* Комбинированный режим выбора: использование label selector вместе со специальным лейблом `autovpa.deckhouse.io/enabled` для формирования объединения подходящих пространств имен.
* Для режима рекомендаций по умолчанию не требуется менять манифесты приложений: объекты VPA создаются и поддерживаются автоматически.
* Настройка VPA на уровне workload и namespace через аннотации и лейблы `autovpa.deckhouse.io/*`.
* Минимальное потребление ресурсов: контроллер работает в одной реплике с низкими требованиями к CPU и памяти.

Подробнее с настройками модуля и примерами его использования можно ознакомиться [в разделе документации модуля](/modules/adaptive-resource-management/).

## Архитектура модуля

{% alert level="info" %}
Для упрощения схемы приняты следующие допущения:

* На схеме показано, что контейнеры разных подов взаимодействуют друг с другом напрямую. Фактически они взаимодействуют через соответствующие сервисы Kubernetes (внутренние балансировщики). Названия сервисов не указываются, если они очевидны из контекста. В остальных случаях название сервиса указано над стрелкой.
* Поды могут быть запущены в нескольких репликах, однако на схеме все поды изображены в одной реплике.
{% endalert %}

## Компоненты модуля

Модуль `adaptive-resource-management` состоит из одного компонента **autovpa-controller**, включающего основной контейнер **autovpa**.

## Взаимодействия модуля

Модуль взаимодействует с компонентом **kube-apiserver** для создания объектов VPA под рабочие нагрузки.
