Модуль [`sdn`](/modules/sdn/) предоставляет функции программно-определяемых сетей (SDN, Software Defined Networking) в Deckhouse Kubernetes Platform (DKP):

- настройку сетевых интерфейсов на узлах;
- дополнительные сети для подов и виртуальных машин;
- IPAM для дополнительных сетей;
- underlay-сети для проброса аппаратных сетевых устройств;
- системные сети для служебного трафика на узлах.

Модуль работает со следующими кастомными ресурсами API-группы `network.deckhouse.io`:

- [ClusterNetwork](/modules/sdn/cr.html#clusternetwork) — определяет общедоступную сеть в масштабе всего кластера;
- [ClusterIPAddressPool](/modules/sdn/cr.html#clusteripaddresspool) — определяет пул IPv4-адресов в масштабе кластера, используемый для IPAM в кластерных сетях;
- IPAddressPool — определяет пул IPv4-адресов в рамках пользовательского неймспейса, используемый для IPAM в сети проекта;
- [IPAddress](/modules/sdn/cr.html#ipaddress) — представляет запрос на IPv4-адрес для дополнительного сетевого интерфейса пода, подключённого к сети проекта;
- ClusterIPAddress — представляет запрос на IPv4-адрес в масштабе всего кластера, для сетевого интерфейса, подключённого к ClusterNetwork или SystemNetwork;
- [IPAddressLease](/modules/sdn/cr.html#ipaddresslease) — запись резервирования выделенного IP-адреса, предотвращающая его повторное присвоение;
- [NodeNetworkInterface](/modules/sdn/cr.html#nodenetworkinterface) — описывает сетевой интерфейс на узле, используется как для обнаружения существующих интерфейсов, так и для создания новых (VLAN, Bond);
- Network — namespaced-ресурс, создаёт выделенную сеть проекта на основе класса сети, заданного администратором в ресурсе NetworkClass;
- NetworkClass — задаёт диапазон VLAN-тегов и узловые сетевые интерфейсы, на основе которых пользователи могут создавать собственные ресурсы Network;
- UnderlayNetwork — обеспечивает прямое подключение физических и виртуальных сетевых интерфейсов узла (PF/VF) к подам через Dynamic Resource Allocation (DRA), в режиме Shared или Dedicated;
- SystemNetwork — создаёт дополнительную сервисную сеть на узлах кластера поверх существующей underlay-сети для служебного трафика.

Подробнее с описанием настройки и примерами использования модуля можно ознакомиться [в разделе документации модуля](/modules/sdn/).

## Архитектура модуля

{% alert level="info" %}
Для упрощения схемы приняты следующие допущения:

* На схеме показано, что контейнеры разных подов взаимодействуют друг с другом напрямую. Фактически они взаимодействуют через соответствующие сервисы Kubernetes (внутренние балансировщики). Названия сервисов не указываются, если они очевидны из контекста. В остальных случаях название сервиса указано над стрелкой.
* Поды могут быть запущены в нескольких репликах, однако на схеме все поды изображены в одной реплике.
{% endalert %}

## Компоненты модуля

Модуль состоит из следующих компонентов:

1. **Controller** (Deployment) — контроллер управляет программно-определяемыми сетями в DKP, выполняя следующие действия:

   - управляет кастомными ресурсами API-группы `network.deckhouse.io`;
   - обслуживает admission-вебхуки для их валидации и мутации через механику [Validating/Mutating Admission Controllers](https://kubernetes.io/docs/reference/access-authn-authz/admission-controllers/);
   - мутирует ресурсы Pod в неймспейсах с меткой `direct-nic-access.network.deckhouse.io/enabled` для внедрения ResourceClaim при пробросе аппаратных сетевых устройств.

   Состоит из одного контейнера **controller**.

1. **Agent** (DaemonSet) — компонент, запускающийся на всех узлах сети и выполняющий следующие операции:

   - настраивает сетевые интерфейсы узла (агрегация портов, объединение в бридж, настройка VLAN-интерфейсов);
   - поднимает дополнительные, underlay- и системные сети;
   - реализует CNI-сервер, к которому по unix-сокету обращается компонент d8-sdn;
   - реализует драйвер Dynamic Resource Allocation (DRA) для API-группы `network.deckhouse.io`, регистрируясь в качестве DRA-плагина в kubelet в редакциях, где доступен ресурс UnderlayNetwork, для проброса физических и виртуальных сетевых устройств в под.

   Agent отвечает за перевод конфигураций узлов кластера и запущенных на них подов в низкоуровневые настройки для сетевых интерфейсов и eBPF-программ, которые реально обрабатывают трафик.

   Состоит из следующих контейнеров:

   - **install-cni-plugin** — init-контейнер, копирует исполняемый файл CNI-плагина `d8-sdn` в каталог `/opt/cni/bin` на узле;
   - **agent** — основной контейнер.

   {% alert level="warning" %}
   У компонента agent есть привилегированный доступ к операционной системе каждого узла. В Linux для этого требуются capabilities:

   - NET_ADMIN
   - SYS_ADMIN
   - BPF

   Контейнер также запускается от имени пользователя root (`runAsUser: 0`), использует `hostNetwork: true` и профиль AppArmor `Unconfined`. Это необходимо для настройки сетевых интерфейсов узла, сетевых пространств имён и загрузки BPF-программ.
   {% endalert %}

1. **D8-sdn** — исполняемый файл CNI-плагина, который запускает компонент containerd в соответствии со [спецификацией CNI](https://www.cni.dev/docs/spec/#cni-operations), например ADD при создании сетевого пространства имён пода и DEL при его удалении. Для настройки сетевых интерфейсов пода d8-sdn взаимодействует с API агента через Unix-сокет и инициирует настройку низкоуровневой конфигурации сети для подов.

1. **Scheduler** (Deployment) — расширение (extender) для kube-scheduler, предлагает узлы для размещения подов в соответствии с настройками сетевых интерфейсов подов.

1. **Cni-plugin-cleaner** (DaemonSet) — Helm `pre-delete` хук модуля, запускаемый контроллером Deckhouse перед удалением модуля [`sdn`](/modules/sdn/), который запускается на каждом узле и удаляет файлы CNI-плагина (исполняемый файл в `/opt/cni/bin` и конфигурацию в `/etc/cni/net.d`), установленные компонентом agent. Не участвует в штатной работе модуля.

1. **Cni-plugin-cleaner-waiter** (Job) — Helm `pre-delete` хук модуля, запускаемый контроллером Deckhouse перед удалением модуля [`sdn`](/modules/sdn/), который ожидает завершения работы DaemonSet `cni-plugin-cleaner` на всех узлах кластера, прежде чем Helm разрешит завершить удаление релиза модуля.

## Взаимодействия модуля

Модуль взаимодействует со следующими компонентами:

1. **Kube-apiserver**:

   - управляет кастомными ресурсами API-группы `network.deckhouse.io`;
   - управляет ресурсами Secret, Pod, Node, Namespace, DeviceClass, ResourceSlice, ResourceClaim и ResourceClaimTemplate.

1. **Kubelet** — регистрируется как DRA-плагин для ресурсов API-группы `network.deckhouse.io`.

С модулем взаимодействуют следующие внешние компоненты:

1. **Kube-apiserver**:

   - вызывает валидацию кастомных ресурсов API-группы `network.deckhouse.io`;
   - вызывает мутацию ресурсов NodeNetworkInterface и Pod;
   - вызывает scheduler extender webhook при подборе узла для пода.

1. **Containerd** — запускает исполняемый файл d8-sdn с определёнными командами в соответствии со спецификацией CNI, например ADD при создании сетевого пространства имён пода и DEL при его удалении.

1. **Kubelet** — вызывает методы PrepareResourceClaims и UnprepareResourceClaims для настройки DRA-ресурсов пода.
