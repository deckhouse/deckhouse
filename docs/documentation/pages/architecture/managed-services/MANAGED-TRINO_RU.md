Модуль [`managed-trino`](/modules/managed-trino/) управляет экземплярами [Trino](https://github.com/trinodb/trino) в Deckhouse Kubernetes Platform (DKP). Trino — это быстрый распределённый SQL-движок с открытым исходным кодом, который создан для аналитики больших данных.
Модуль предоставляет:

* **Автоматическое развёртывание** — создаёт экземпляр Trino при помощи простой YAML-конфигурации;
* **Standalone** — поддерживает установку одиночного экземпляра;
* **Внешние подключения** — поддерживает работу с хранилищем метаданных [Hive Metastore](https://github.com/apache/hive), а также с S3-хранилищем;
* **Управление конфигурацией** — отдельный ресурс [TrinoClass](/modules/managed-trino/cr.html#trinoclass) для шаблонизации создания сервиса и гибкой валидации пользовательских параметров;
* **Статус** — отображает текущее состояние развёрнутого экземпляра Trino.

Подробнее с настройками модуля и примерами его использования можно ознакомиться [в документации модуля](/modules/managed-trino/).

## Архитектура модуля

Для упрощения схемы приняты следующие допущения:

* На схеме показано, что контейнеры разных подов взаимодействуют друг с другом напрямую. Фактически они взаимодействуют через соответствующие сервисы Kubernetes (внутренние балансировщики). {% endalert %}

## Компоненты модуля

Модуль состоит из следующих компонентов:

1. managed-trino-operator (Deployment) — оператор Kubernetes, состоящий из одного контейнера manager и выполняющий следующие операции:

   - согласование состояния кастомных ресурсов [Trino](/modules/managed-trino/cr.html#trino) во всех пользовательских неймспейсах. Ресурс Trino определяет настройки экземпляра Trino;

   - создание и управление ресурсами Deployment, Service, Secret и ConfigMap, относящимися к экземпляру Trino;

   - валидация и мутация кастомных ресурсов Trino с помощью механизмов [Validating/Mutating Admission Controllers](https://kubernetes.io/docs/reference/access-authn-authz/admission-controllers/).

1. d8ms-trn-\<INSTANCE_NAME> (Deployment) — компонент, состоящий из одного контейнера trino, который выполняет запуск экземпляра Trino.

## Взаимодействия модуля

Модуль взаимодействует со следующими компонентами:

1. Инстанс Hive Metastore — обрабатывает данные в хранилище метаданных.

1. S3-хранилище — обрабатывает данные в объектном хранилище.

1. kube-apiserver:

   - управляет кастомными ресурсами Trino;
   - следит за кастомными ресурсами TrinoClass;
   - управляет ресурсами Deployment, Service, Secret и ConfigMap.

С модулем взаимодействуют следующие внешние компоненты:

1. kube-apiserver — обрабатывает запросы на валидацию и мутацию кастомных ресурсов Trino.

1. Пользовательские приложения — отправляют запросы к экземпляру Trino.
