Легковесные логи в Deckhouse Virtualization Platform (DVP) позволяют просматривать текущие логи подов в проектах и во всём кластере без развёртывания хранилища и настройки доставки логов. Легковесные логи читаются напрямую из создаваемых CRI файлов на узле, поэтому для их просмотра не требуется включать модули [`loki`](/modules/loki/) и [`log-shipper`](/modules/log-shipper/) и не нужно выделять под них ресурсы — дополнительно расходуется только место на диске, которое логи занимают и без этого механизма.

Доступ к легковесным логам предоставляется через Loki-совместимый HTTP API, поэтому они доступны в Grafana и в веб-интерфейсе платформы так же, как обычные логи из Loki. Получать легковесные логи можно c помощью LogQL, а не только используя команду `d8 k logs`.

## Преимущества легковесных логов

Легковесные логи в DVP имеют следующие преимущества:

- Отсутствие накладных расходов. В отличие от Loki, легковесные логи не требуют отдельного хранилища и ресурсов на его работу. Логи читаются в режиме реального времени из файлов, которые в любом случае лежат на диске узла (т.к. создаются CRI).
- Loki-совместимый API. Логи можно смотреть не через `d8 k logs` по одному поду, а одним запросом сразу по всему доступному массиву логов, используя Grafana. Можно строить графики, делать выборки и агрегации на LogQL.
- Гибкая фильтрация в UI. В веб-интерфейсе платформы можно фильтровать логи по различным параметрам.
- Единый API для всех вариантов хранения логов. Работа с легковесными логами происходит через тот же Loki-совместимый интерфейс, что и с остальными инструментами логирования DVP.

{% alert level="info" %}
Так как легковесные логи и хранилища на базе Loki используют единый Loki-совместимый API, их можно использовать одновременно.
{% endalert %}

## Особенности и ограничения

Легковесные логи в DVP имеют следующие особенности использования и ограничения:

- Логи пода перестают быть доступными для запроса сразу после его удаления из кластера. Долговременного хранения в этом режиме нет.
- Логи читаются из файлов в момент выполнения запроса, поэтому запросы с широким временным диапазоном обрабатывают больше данных, чем аналогичный запрос к индексированному хранилищу, такому как Loki.

## Включение и отключение

Легковесные логи реализуются средствами модуля `observability`. Если модуль включен, они включены по умолчанию и не требуют дополнительной настройки.

Чтобы отключить легковесные логи, задайте в конфигурации модуля [`observability`](/modules/observability/) значение параметра `lightweightLogs.enabled : false`:

```yaml
apiVersion: deckhouse.io/v1alpha1
kind: ModuleConfig
metadata:
  name: observability
spec:
  version: 1
  enabled: true
  settings:
    lightweightLogs:
      enabled: false
```

Чтобы включить или выключить легковесные логи в веб-интерфейсе платформы, перейдите в раздел с настройками модуля `observability`, выберите «Дополнительные настройки» → «Lightweight logs» и включите/выключите параметр `Enabled`.

## Просмотр логов

Для просмотра легковесных логов в веб-интерфейсе платформы перейдите в раздел «Мониторинг» → «Обзор данных» (на уровне кластера либо в конкретном проекте). Здесь выберите источник данных `lightweight-logs`.

В выборку попадают логи всех запущенных на момент запроса подов в выбранном неймспейсе либо во всех неймспейсах кластера (включая системные).

Просмотр логов требует наличия у пользователя [соответствующих прав](/modules/observability/permissions.html) (`resources: ["logs"]`).
