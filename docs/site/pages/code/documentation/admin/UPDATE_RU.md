Команда `d8code update` обновляет существующий экземпляр Deckhouse Code. Как и [установка](install.html), она работает в двух типах окружения, которые выбираются флагом `--env-type`:

- `omnibus` (по умолчанию) — обновление пакета на локальном узле.
- `k8s` — обновление экземпляра в кластере Kubernetes.

Тип окружения определяется по флагу `--env-type`, затем по переменной окружения `D8CODE_ENV_TYPE`, затем по полю конфигурации `env.type`; значение по умолчанию — `omnibus`. Для `--env-type=k8s` обязательны аргумент `<name>` с именем экземпляра и флаг `--namespace`.

{% alert level="info" %}
Команды `install` и `update` не взаимозаменяемы. `install` не изменяет уже существующий экземпляр, а `update` не создаёт отсутствующий. Если выбрана неподходящая команда, `d8code` сообщает, какую команду использовать, и завершается с кодом `0` без внесения изменений.
{% endalert %}

## Обновление в окружении omnibus

При обновлении в окружении omnibus заменяется пакет на локальном узле.

{% alert level="warning" %}
Обновление из репозитория пока недоступно. Используйте флаг `--local-file` с заранее загруженным файлом пакета.
{% endalert %}

Обновление из локального файла пакета:

```shell
sudo d8code update --local-file /path/to/deckhouse-code.deb
```

Краткая форма флага — `-f`. Значение `--env-type=omnibus` используется по умолчанию, поэтому его можно не указывать.

### Проверки перед обновлением

Выполняются те же проверки, что и при установке, но с одним отличием на последнем шаге:

1. Файл пакета существует по указанному пути.
1. Расширение файла — `.deb` или `.rpm`.
1. Определённый дистрибутив узла использует тот же формат пакета: `.deb` для Debian, Ubuntu и Astra; `.rpm` для RED OS, RHEL, CentOS, AlmaLinux, Rocky и Fedora.
1. Имя пакета из метаданных файла — `deckhouse-code`.
1. Пакет уже установлен. Если он не установлен, `d8code` выводит предупреждение, предлагает команду `install` и завершается с кодом `0`.

Права суперпользователя нужны только для запуска пакетного менеджера, поэтому проверки можно выполнить без `sudo`:

```shell
d8code update --local-file /path/to/deckhouse-code.deb
```

После успешных проверок `d8code` выполняет `dpkg -i` для пакетов `.deb` или `dnf upgrade -y` для пакетов `.rpm`.

{% alert level="info" %}
Если обновление пакета `.deb` завершилось ошибкой из-за неудовлетворённых зависимостей, выполните `apt-get install -f` и повторите команду.
{% endalert %}

### Проверка результата

Проверьте установленную версию после обновления:

```shell
d8code version
```

Вывод имеет вид `<version>-<commit> (Golang: go<goversion>)`.

## Обновление в окружении Kubernetes

При обновлении в Kubernetes объекты пересобираются из текущей конфигурации, и в кластере применяются различия. Объекты, которые больше не входят в состав экземпляра, удаляются.

### Перед обновлением

Выполните следующие шаги:

- Приведите секцию конфигурации `legacy` к целевому состоянию.
- Проверьте конфигурацию: `d8code config validate --with-kube`.
- Убедитесь, что доступны учётные данные registry и файл с дайджестами образов, как при [установке](install.html).
- Рассмотрите включение [режима обслуживания](configuration/maintenance-mode.html), чтобы пользователи не вносили изменения во время обновления.

### Запуск обновления

Просмотрите изменения перед их применением:

```shell
d8code update code --env-type=k8s --namespace d8-code --dry-run
```

Примените изменения:

```shell
d8code update code --env-type=k8s --namespace d8-code
```

При успешном завершении команда выводит `update complete`. Применённым объектам присваиваются метки целевой версии, поэтому повторный запуск приводит к тому же состоянию.

Если переменные окружения не используются, передайте учётные данные registry явно:

```shell
d8code update code \
  --env-type=k8s \
  --namespace d8-code \
  --registry-url registry.example.com \
  --registry-username USERNAME \
  --registry-password PASSWORD \
  --images-digests /path/to/images-digests.json
```

Замените `USERNAME` и `PASSWORD` на учётные данные registry, а `registry.example.com` — на адрес registry.

### Проверка результата

Отследите обновление рабочих нагрузок в целевом неймспейсе:

```shell
d8 k -n d8-code get pods
```

Проверьте состояние обновления конкретного deployment:

```shell
d8 k -n d8-code rollout status deployment/code-webservice-default
```

## Переход с управления через оператор

Если экземпляр всё ещё управляется оператором Deckhouse Code, переведите его на управление через CLI отдельной командой:

```shell
d8code legacy-migrate --name code --namespace d8-code
```

Миграция выполняется по фазам с запросом подтверждения перед каждой. Чтобы выполнить одну фазу, укажите флаг `--phase`. Чтобы посмотреть запланированные изменения без их применения, добавьте флаг `--dry-run`.

{% alert level="warning" %}
Миграция изменяет топологию работающего экземпляра. Сначала выполните её с флагом `--dry-run` и запланируйте окно обслуживания.
{% endalert %}
