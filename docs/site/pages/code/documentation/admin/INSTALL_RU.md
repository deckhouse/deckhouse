`d8code` — инструмент командной строки для установки экземпляра Deckhouse Code. Он поддерживает два типа окружения, которые выбираются флагом `--env-type`:

- `omnibus` (по умолчанию) — установка Deckhouse Code пакетом на локальный узел.
- `k8s` — развёртывание экземпляра Deckhouse Code в кластере Kubernetes.

Все команды поддерживают флаг `--help`.

## Выбор типа окружения

`d8code` определяет тип окружения по первому заданному источнику в следующем порядке:

1. Флаг `--env-type`.
1. Переменная окружения `D8CODE_ENV_TYPE`.
1. Поле `env.type` в файле конфигурации.
1. Значение `omnibus` по умолчанию.

Тип окружения определяет допустимые аргументы. Для `--env-type=k8s` обязательны аргумент `<name>` с именем экземпляра и флаг `--namespace`. Для `--env-type=omnibus` они не применяются, и их передача завершает команду с ошибкой.

## Файл конфигурации

`d8code` читает конфигурацию в формате YAML из `~/.d8code/config`. Чтобы задать другой путь, используйте переменную окружения `D8CODE_CONFIG`.

```yaml
log:
  format: simple
cache:
  dir: /home/user/.d8code/cache
env:
  type: omnibus
imagesDigests: /path/to/images-digests.json
legacy:
  network: {}
  appConfig: {}
  gitData: {}
  storages: {}
  features: {}
  backup: {}
  scaling:
    targetUserCount: 0
```

Секция `legacy` повторяет спецификацию `CodeInstance` и обязательна для установки в Kubernetes. Проверьте её перед установкой:

```shell
d8code config validate
```

Добавьте флаг `--with-kube`, чтобы дополнительно проверить конфигурацию в кластере. Если файл конфигурации отсутствует, команда выводит уведомление и завершается с кодом `0`.

## Установка в окружении omnibus

При установке в окружении omnibus Deckhouse Code размещается на локальном узле с помощью пакетного менеджера узла.

{% alert level="warning" %}
Установка из репозитория пока недоступна. Используйте флаг `--local-file` с заранее загруженным файлом пакета.
{% endalert %}

Установка из локального файла пакета:

```shell
sudo d8code install --local-file /path/to/deckhouse-code.deb
```

Значение `--env-type=omnibus` используется по умолчанию, поэтому его можно не указывать. Краткая форма флага — `-f`.

### Поддерживаемые дистрибутивы

Формат пакета определяется по расширению файла и должен совпадать с форматом дистрибутива узла:

| Формат пакета | Дистрибутивы |
| --- | --- |
| `.deb` | Debian, Ubuntu, Astra |
| `.rpm` | RED OS, RHEL, CentOS, AlmaLinux, Rocky, Fedora |

Дистрибутив узла определяется по файлу `/etc/os-release`, а при его отсутствии — по release-файлам в стиле Red Hat. При несовпадении формата или для неподдерживаемого дистрибутива команда завершается до внесения изменений.

### Проверки перед установкой

`d8code` выполняет проверки в следующем порядке и останавливается на первой неуспешной:

1. Файл пакета существует по указанному пути.
1. Расширение файла — `.deb` или `.rpm`.
1. Определённый дистрибутив узла использует тот же формат пакета.
1. Имя пакета из метаданных файла — `deckhouse-code`. Любой другой пакет отклоняется.
1. Пакет ещё не установлен. Если он установлен, `d8code` выводит предупреждение, предлагает команду `update` и завершается с кодом `0`.

Права суперпользователя нужны только на последнем шаге — при запуске пакетного менеджера. Поэтому проверить файл пакета можно без `sudo`:

```shell
d8code install --local-file /path/to/deckhouse-code.deb
```

После успешных проверок `d8code` выполняет `dpkg -i` для пакетов `.deb` или `dnf install -y` для пакетов `.rpm`.

{% alert level="info" %}
Если установка пакета `.deb` завершилась ошибкой из-за неудовлетворённых зависимостей, выполните `apt-get install -f` и повторите команду.
{% endalert %}

## Установка в окружении Kubernetes

При установке в Kubernetes из секции конфигурации `legacy` создаётся объект `CodeInstance`, а полученные объекты применяются в кластере.

### Предварительные требования

Подготовьте следующее:

- Файл конфигурации с заполненной секцией `legacy`.
- Учётные данные container registry — либо во флагах `--registry-url`, `--registry-username` и `--registry-password`, либо в переменных окружения `D8CODE_REGISTRY_URL`, `D8CODE_REGISTRY_USERNAME` и `D8CODE_REGISTRY_PASSWORD`. Все три значения обязательны.
- Файл с дайджестами образов — во флаге `--images-digests`, в переменной окружения `D8CODE_IMAGES_DIGESTS` или в поле конфигурации `imagesDigests`.
- Заданный домен кластера. Если домен кластера пуст, установка завершается с ошибкой.

### Запуск установки

Посмотрите объекты без изменения кластера:

```shell
d8code install code --env-type=k8s --namespace d8-code --dry-run
```

Флаг `--dry-run` выводит объекты в формате YAML вместо их применения. Используйте его, чтобы проверить результат перед первой установкой.

Примените объекты:

```shell
d8code install code --env-type=k8s --namespace d8-code
```

Краткая форма флага `--namespace` — `-n`. При успешном завершении команда выводит `install complete`.

Если экземпляр уже работает в этом неймспейсе, `d8code` сообщает, что он уже установлен, и завершается без изменений. Для работающего экземпляра используйте [процедуру обновления](update.html).

Если переменные окружения не используются, передайте учётные данные registry явно:

```shell
d8code install code \
  --env-type=k8s \
  --namespace d8-code \
  --registry-url registry.example.com \
  --registry-username USERNAME \
  --registry-password PASSWORD \
  --images-digests /path/to/images-digests.json
```

Замените `USERNAME` и `PASSWORD` на учётные данные registry, а `registry.example.com` — на адрес registry.

### Проверка результата

Проверьте созданные рабочие нагрузки в целевом неймспейсе:

```shell
d8 k -n d8-code get pods
```

## Журналирование

Флаги журналирования одинаковы для обоих типов окружения:

```shell
d8code install --local-file /path/to/deckhouse-code.deb --log-format json
```

Флаг `--log-format` принимает значения `simple` (по умолчанию) или `json` и имеет приоритет над полем конфигурации `log.format`. Флаг `--log-color` управляет цветным выводом в формате `simple`: он автоматически отключается, если вывод не является терминалом, а вывод в формате `json` никогда не окрашивается.

Чтобы узнать версию используемого инструмента:

```shell
d8code version
```
