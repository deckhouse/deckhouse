Эта интеграция позволяет автоматически импортировать результаты проверок безопасности из Deckhouse Code в DefectDojo, единую систему управления уязвимостями.

![Форма интеграции DefectDojo](/images/code/defect_dojo_integration_form_ru.png)

## Предварительные требования

Перед настройкой интеграции убедитесь, что:

- доступен экземпляр DefectDojo;
- получен API-токен DefectDojo с правом импорта результатов сканирования;
- в проекте Deckhouse Code настроена роль **Maintainer**;
- ваш CI-конвейер формирует поддерживаемые артефакты проверок безопасности.

## Настройка интеграции DefectDojo

Чтобы настроить интеграцию:

1. Откройте проект в Deckhouse Code.
1. Перейдите в раздел «Настройки» → «Интеграции» → «DefectDojo».
1. Установите флажок «Активные».
1. Заполните поля блока «Соединение»:
   - «URL DefectDojo» — базовый URL экземпляра DefectDojo;
   - «API-токен» — API-токен DefectDojo.
1. Заполните поля блока «Параметры импорта по умолчанию», которые применяются при импорте отчётов:
   - «Название продукта» (опционально) — название продукта в DefectDojo. По умолчанию используется полный путь проекта;
   - «Тип продукта» (опционально) — тип продукта в DefectDojo, используется при автоматическом создании продукта;
   - «Название активности» (опционально) — название активности (Engagement) в DefectDojo. По умолчанию используется имя ветки или тега, на котором выполнялся конвейер;
   - «Минимальная критичность» — несоответствия с меньшей критичностью не импортируются;
   - «Автоматически создавать контекст» — создавать в DefectDojo продукт и активность, если они не существуют;
   - «Импортированные находки» — помечать импортированные несоответствия как активные;
   - «Подтверждённые находки» — помечать импортированные несоответствия как подтверждённые;
   - «Закрывать старые находки» — закрывать несоответствия, которых больше нет в отчёте.
1. Нажмите «Сохранить изменения».

Интеграция доступна также на уровне группы и экземпляра — в этом случае проекты наследуют её настройки.

### Проверка подключения

Чтобы проверить доступность DefectDojo и корректность API-токена, нажмите «Проверить настройки» на странице интеграции.

## Работа интеграции

### Автоматический импорт результатов сканирования

После завершения каждого CI-конвейера, сформировавшего отчёты проверок безопасности, Deckhouse Code автоматически импортирует их в DefectDojo через API `reimport-scan`.

Поддерживаются результаты следующих типов сканирования:

- SAST;
- Secret detection;
- Dependency scanning;
- Container scanning;
- DAST.

Отчёты отправляет сам Deckhouse Code, поэтому в конвейере не нужны ни отдельная задача, ни учётные данные DefectDojo в CI-переменных.

### Сопоставление сущностей в DefectDojo

По умолчанию Deckhouse Code использует следующие соответствия:

- **Product** — полный путь проекта (или заданное значение «Название продукта»);
- **Активность (Engagement)** — имя ветки или тега, на котором выполнялся конвейер (или заданное значение «Название активности»);
- **Test** — имя CI-задачи, сформировавшей отчёт.

Тест закрепляется за конкретной задачей сканирования, поэтому сканеры не закрывают несоответствия друг друга.

### Параметры импорта

При импорте результатов Deckhouse Code передаёт в DefectDojo значения из блока «Параметры импорта по умолчанию», а также идентификатор конвейера, SHA коммита и имя ветки или тега, к которым относится отчёт.

## Хранение API-токена

- Используйте отдельную сервисную учётную запись DefectDojo с правами только на импорт результатов сканирования.
- Токен хранится в зашифрованном виде и после сохранения больше не отображается: чтобы заменить его, введите новый в поле «Введите новый API-токен».
- Чтобы не копировать токен в каждый проект, настройте интеграцию на уровне группы или экземпляра.
