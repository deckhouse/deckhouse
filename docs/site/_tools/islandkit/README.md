# Шапка сайта: остров islandKit

Шапку рисует компонент `site-header` из пакета `islandkit`. Это **контентный**
остров: его разметка обязана быть в ответе сервера, поэтому она не собирается
скриптом после загрузки, а печатается заранее — тем же Vue-компонентом, что
потом работает в браузере, через серверный рендеринг Vue.

Одна шапка на продукт и язык, как этот сайт и устроен: фрагменты публикуются в
`{ru,en}/includes/header*.html`, а nginx вставляет их по SSI в страницы
документации и в страницы модулей на Hugo.

## Как это попадает в сборку

Стадия `site-islandkit-artifact` (`../../werf-islandkit.inc.yaml`) ставит
`islandkit` из npm по закреплённой версии, запускает `render-header.mjs` и
отдаёт три вещи сборке сайта: фрагменты, их индекс и бандл. Импорт прописан в
`../../werf-web-frontend.inc.yaml`, без условия по окружению — шапка нужна в
любой сборке.

Поэтому **в репозитории ничего сгенерированного не лежит**: `_includes/_generated/`,
`assets/islandkit/` и `_data/islandkit_header.json` внесены в `.gitignore`.

Меню стадия берёт оттуда же, откуда Jekyll: в прод-окружениях импортом из
`site-external-artifacts` (данные из API), иначе — из `_data/topnav*.json`
репозитория. Без этого импорта шапка застыла бы на копии меню из репозитория,
пока остальной сайт обновляется.

### Обновить версию библиотеки

1. поднять `$islandkitVersion` в `../../werf-islandkit.inc.yaml`;
2. пересобрать. Всё остальное — адрес бандла в `head-site.html`, список
   продуктов в шаблоне — читается из `_data/islandkit_header.json`, который
   печатает та же стадия.

`$vueVersion` там же закреплён отдельно и должен оставаться в пределах
`peerDependencies` библиотеки.

## Что где лежит

| Путь | Что это |
| --- | --- |
| `render-header.mjs` | печатает фрагменты и копирует бандл |
| `../../_data/header-products.json` | мега-меню «Продукты» — данные, которые раньше были вписаны в шаблон трижды |
| `../../_sass/components/_islandkit-header.scss` | оформление: значения переменных `--ik-*` |
| `../../_includes/header.html` | точка входа: выбирает фрагмент по продукту и языку |
| `../../_includes/header-legacy.html` | прежняя шапка; ею пользуется сборка внутри кластера (`site.mode == module`) |

Генерируемое (в git не хранится): `../../_includes/_generated/`,
`../../_data/islandkit_header.json`, `../../assets/islandkit/<версия>/`.

## Перегенерировать локально

Нужно редко — обычно достаточно пересобрать. Но если хочется посмотреть
фрагменты глазами:

```bash
npm install --no-save islandkit@<версия> vue@3 @vue/server-renderer@3
node _tools/islandkit/render-header.mjs
```

Для неопубликованной сборки библиотеки:

```bash
node _tools/islandkit/render-header.mjs --islandkit <путь к чекауту islandKit>
```

Флаг означает «пакет взят из рабочей копии», и тогда каталог ассетов получает
суффикс `-dev`: сборка из рабочего дерева не должна занимать адрес
опубликованной версии с тем же номером — адрес в пути на то и неизменяемый.

Есть ещё `--site <путь>`, если запускать скрипт не из этого дерева.

## Что осталось на прежней шапке

Сборка внутри кластера (`site.mode == module`) читает другое меню
(`modules/810-documentation/images/web/site/_data/topnav.yml`) и собирается
отдельным werf-файлом, поэтому она пользуется `header-legacy.html`. Скрипты той
шапки — `language-switch.js` и `adaptive/header-mobile.js` — подключены в
`documentation/_includes/head-local.html`, единственном файле, который попадает
на страницу ровно в этом режиме.
