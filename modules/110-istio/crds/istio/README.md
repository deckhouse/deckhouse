# Istio CRD compatibility bundle

This directory is the single, cluster-wide Istio CRD bundle installed by Deckhouse.
It intentionally contains one `CustomResourceDefinition` object per YAML file.

## Sources

* The 14 Istio configuration CRDs are copied from the generated bundle in the
  Istio repository at tag `1.29.6` (`manifests/charts/base/crds/crd-all.gen.yaml`,
  generated by Istio's Cue OpenAPI generator). Istio 1.29.6 is the source of
  truth for these schemas and storage versions.
* `istiooperators.install.istio.io` is retained from Istio 1.25's operator CRD
  bundle.
* The five `sailoperator.io` CRDs are retained from the Sail Operator bundle
  shipped with Istio 1.25. They are required while Istio 1.25 remains supported.

The bundle is a compatibility superset: configuration APIs retain every served
upstream version, including legacy `v1alpha3` and `v1beta1` versions. Kubernetes
is responsible for retaining old `status.storedVersions`; this bundle must not
manually edit that status.

## Updating

Run `./_update.py` with paths to the freshly downloaded upstream files, for
example:

```shell
./_update.py \
  --istio-config /tmp/istio-1.29.6/crd-all.gen.yaml \
  --istio-operator /tmp/istio-1.25/crd-operator.yaml \
  --sail-dir /tmp/istio-1.25
```

The script splits multi-document YAML without modifying objects, writes one
file per CRD, and checks the expected 14 configuration and six operator CRD
names. It also checks that every CRD has exactly one storage version and that
legacy configuration versions remain served.
