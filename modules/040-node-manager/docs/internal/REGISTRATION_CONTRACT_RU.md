---
title: "Контракт регистрации cloud-provider"
description: Данные, которые модуль cloud-provider публикует для node-manager и node-controller.
---

Модуль cloud-provider публикует одинаковые регистрационные данные в legacy Secret
`kube-system/d8-node-manager-cloud-provider` и в провайдерский Secret
`kube-system/d8-node-manager-cloud-provider-<id>`. В зависимости от типа поля содержат обычные
строки или JSON. Загрузчик возвращает ошибку на отсутствующих, пустых или некорректных
обязательных данных до начала рендеринга ресурсов.

Оба секрета должны нести лейбл `cloud-provider.deckhouse.io/registration`. Контракт node-controller
проверяет только на legacy-секрете, но список kind-ов InstanceClass он собирает по всем помеченным
секретам в `kube-system`, читая из каждого `instanceClassKind` и `instanceClassAPIVersion`.
Регистрация без лейбла отрендерит ресурсы и молча сломается в другом месте: watch за InstanceClass
не запустится, а admission NodeGroup не сможет разрешить класс. Публикуйте оба секрета, с лейблом и
одинаковым содержимым.

## Общие поля

Каждый провайдер публикует:

| Ключ | Тип | Назначение |
|---|---|---|
| `type` | string | Имя провайдера в нижнем регистре. |
| `region` | string | Регион; для провайдера без регионов используется `default`. |
| `zones` | JSON-массив строк | Доступные зоны. Для провайдера без зон используется `["default"]`, пустой список допустим. |
| `instanceClassKind` | string | Kind провайдерского InstanceClass. |
| `instanceClassAPIVersion` | string | Served-версия InstanceClass, с которой должен работать node-controller. |
| `<type>` | JSON-объект | Данные провайдера, доступные шаблонам как `.provider`; объект может быть пустым. |

Регистрация должна включать хотя бы один движок управления узлами: CAPI или MCM.

Пустой список зон означает состояние, а не ошибку в регистрации. Discovery мог ещё не найти зоны:
так публикует их OpenStack в hybrid-режиме, пока не отработал хук cloud-data. node-controller
пропускает NodeGroup, которым нужна зона, и продолжает обслуживать всё остальное. Поэтому провайдер
публикует пустой список, а не выдуманное имя зоны. Имя зоны уходит в API облака, и выдуманное
переименует MachineClass и пересоздаст узлы группы.

## Поля CAPI

CAPI-провайдер публикует всю группу целиком:

| Ключ | Тип |
|---|---|
| `capiClusterName` | string |
| `capiClusterKind` | string |
| `capiClusterAPIVersion` | group/version |
| `capiMachineTemplateKind` | string |
| `capiMachineTemplateAPIVersion` | group/version |

Обе API-версии должны содержать группу и версию. Файлы из
`d8-cloud-provider-<type>-capi` описаны контрактами cluster-template и machine-template в этом
каталоге.

Legacy-ключи `capiClusterAPIGroup` и `capiMachineTemplateAPIGroup` не входят в контракт: группа
вычисляется из соответствующей API-версии.

## Поля MCM

MCM-провайдер публикует непустой `machineClassKind`. Провайдер без поддержки MCM может не
публиковать этот ключ или оставить его пустым. Провайдер, поддерживающий оба движка, публикует
и CAPI-группу, и непустой `machineClassKind`.

`sshPublicKey` необязателен и используется только теми провайдерами, которым он нужен.

`capiMachineDeploymentSpecPatch` объявлен устаревшим: OpenStack, последний провайдер в дереве,
который его публиковал, объявляет `failureDomain` в шаблоне машины. Ключ уберут, когда на него
перестанут опираться внешние провайдеры, так что новому провайдеру добавлять его не нужно.

## Проверка и версии

node-controller проверяет этот контракт начиная с Deckhouse 1.78. Обязательны `type`, `region`,
`instanceClassKind`, `instanceClassAPIVersion` и поддерево `<type>`. Группа CAPI публикуется
целиком либо не публикуется вовсе, а регистрация, не включающая ни одного движка, отклоняется. До
1.78 неполная регистрация принималась и приводила к наполовину отрендеренным ресурсам.

Внешний провайдер, который публикует меньше, должен быть обновлён до перехода кластера на 1.78.
Иначе ресурсы провайдера перестанут рендериться, а зависящие от них NodeGroup сообщат об ошибке.
