## Пиринг кластеров

{% alert level="warning" %}
Экспериментальная функция, доступна только в редакции Ultimate/EE.
{% endalert %}

Если администратор объединил кластер с другими кластерами (подробнее — [в разделе «Пиринг кластеров»](advanced_usage.html#пиринг-кластеров) расширенного использования), под обращается к подам других кластеров по IP-адресу, а сервис может использовать бэкенды других кластеров.

### Поды других кластеров

Под обращается к поду другого кластера по его IP-адресу, как к поду своего кластера. NAT нет: принимающий под видит адрес пода-клиента.

DNS-имён у подов и сервисов других кластеров нет. Чтобы обращаться к приложению другого кластера по имени, сделайте его сервис глобальным.

### Глобальные сервисы

Глобальный сервис использует свои бэкенды и бэкенды сервиса с тем же именем и в том же пространстве имён в соседних кластерах. Клиенты обращаются к нему по имени и адресу в своём кластере.

Сервис настраивается аннотациями:

| Аннотация | Значение |
|---|---|
| `network.deckhouse.io/global-service-mode` | `Local` — сервис локальный (так же без аннотации).<br>`ImportOnly` — использует бэкенды соседей, свои им не предлагает.<br>`ImportAndExport` — использует бэкенды соседей и предлагает им свои |
| `network.deckhouse.io/global-service-traffic-distribution` | `Any` (по умолчанию) — бэкенды всех кластеров.<br>`PreferLocalCluster` — свои бэкенды, пока есть готовые.<br>`PreferRemoteCluster` — бэкенды соседей, пока есть готовые |

Неизвестный режим означает `Local`, неизвестное распределение — `Any`. Распределение действует только в режимах `ImportOnly` и `ImportAndExport`. Изменения действуют без перезапуска подов; открытые соединения не переносятся.

Имя, пространство имён и порты (с именами) сервиса должны совпадать во всех кластерах.

Headless-сервис (`clusterIP: None`) тоже может быть глобальным: его DNS-имя возвращает адреса подов этого и соседних кластеров. Распределение трафика на него не действует. Поды StatefulSet за таким сервисом называйте по-разному в разных кластерах, например с именем кластера: одинаковые имена подов из разных кластеров конфликтуют в DNS.

Типовые задачи:

| Задача | Что сделать |
|---|---|
| Балансировать по репликам всех кластеров | `global-service-mode: ImportAndExport` в каждом кластере |
| Использовать свои реплики, а соседей — как резерв | Дополнительно `global-service-traffic-distribution: PreferLocalCluster` |
| Использовать приложение, которого нет в своём кластере | В своём кластере — сервис с `ImportOnly`, в кластере с приложением — с `ImportAndExport` |
| Увести нагрузку из кластера, не останавливая реплики | В этом кластере `ImportOnly` и `PreferRemoteCluster`. После обслуживания — вернуть `ImportAndExport` и убрать распределение |

Пример:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: api
  namespace: shop
  annotations:
    network.deckhouse.io/global-service-mode: ImportAndExport
    network.deckhouse.io/global-service-traffic-distribution: PreferLocalCluster
spec:
  selector:
    app: api
  ports:
  - name: http
    port: 80
    targetPort: 8080
```

Когда объединение с соседом разорвано, его бэкенды удаляются из глобальных сервисов, а соединения с его подами обрываются. Временный отказ связи между кластерами объединение не разрывает.
